# 今回の営業の接続復帰

2026-10-20に、ユーザーが新規営業の開始と、接続が戻った際の自動継続を依頼。
キャンペーン `kz-20261020-163105` の最初の1件は、この会話で送信・検証済み。

`resumable_campaign.py` は、今回のキャンペーンを別のCodex実行へ明示的に引き継ぐ方式の候補。ユーザーは別実行への引き継ぎとGoogleマップ閲覧を許可し、`/goal` で450件完了までの継続を指示した。親会話でGoogleマップ閲覧の成功を確認し、今回分の別実行を起動済み。現時点の `automatic_recovery_verified` は false。単体テストは通信断・復帰を模擬しており、Macの実際のWi-Fi切断や実送信中の切断は未検証。

- 引数なしの実行は、接続と計画を表示するだけ。送信しない。
- `--run` は、引き継ぎの明示指示を受けてから起動する。1社ずつ、調査・画像生成・下書き確認・予約・送信・送信済み確認を実行する。
- 定期実行は登録しない。今回分のみ。日本日付・直近24時間の共通450件制限、Gmailの全件カウントを維持する。
- 接続断は待機し、接続復帰時にSQLiteと台帳を再確認する。送信結果が不明なら送信をやり直さず、Gmailの送信済みを読み取って確認する。
- 未確定の送信結果、認証・上限・その他ジョブの異常で停止する。停止を無視して別アカウント・SMTPへ切り替えない。
- 状態は `runs/<campaign>/recovery/status.json`、各実行ログは同じディレクトリに保存する。
- 停止する場合は、そのディレクトリに `STOP` ファイルを作る。再起動の際に勝手に削除しない。
- Macと実行プロセスの稼働が必要。Macの再起動やCodexプロセス終了後に勝手に再起動する設定は作らない。

```sh
# 状態と計画だけ確認
python3 local-web-sales/daily-outreach/resumable_campaign.py

# 別のCodex実行への引き継ぎを明示的に指示された後のみ
python3 local-web-sales/daily-outreach/resumable_campaign.py --run
```
