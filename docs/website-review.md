# 営業候補のサイト確認

2026年10月20日のユーザー指示により、候補発見と改善点の確認をCodexで行う。メール送信は別途ユーザーが指示したときだけ開始する。

## 候補発見

全国・業種制限なし。Googleマップ、通常のウェブ検索、公開の業界団体・商工会等の一覧を組み合わせる。地域・業種・発見元を記録し、同じ地域や飲食・美容だけに連続して偏らないよう検索対象を切り替える。一覧の情報は公式サイトとGoogleマップで再確認する。

既存の必須条件であるGoogleマップ評価3.0以上・口コミ10件以上、営業実態、公開メール、重複・配信失敗・営業拒否の除外を維持する。Googleマップの評価・口コミがない事業者を今回の変更だけで送信対象に加えない。全業種の網羅や均等な配分を保証するものではない。

## Codexによる閲覧確認

提案画像を作る前に、公式サイトのトップ、主なサービス、問い合わせ・予約案内を開く。利用できるブラウザでスマホ幅390pxとデスクトップ幅1280pxを確認し、確認後は一時的な画面幅の変更を戻す。読むだけで確認し、フォーム送信、予約、会員登録、電話発信は行わない。

確認対象は以下の6項目。問題の有無を断定できない場合は「未確認」とする。

1. スマホで本文やナビゲーションが読めるか。横はみ出し、文字の重なり、内容の欠けがないか。
2. 問い合わせ先や予約方法にたどり着けるか。案内リンクが見えるか、必要な情報を確認できるか。
3. 主なサービス、対応地域、所在地・連絡先など、利用判断に必要な情報を見つけられるか。料金非公開だけでは問題としない。
4. 関連する画像・メニュー・リンクが実際に表示されるか。一度の接続失敗や自動閲覧制限をサイトの不具合と決めつけない。
5. サービスから問い合わせへの移動が分かりやすいか。電話専用など、事業者が指定した連絡方針を不具合扱いしない。
6. 営業情報に明確な矛盾や期限切れの案内がないか。更新日が古い、見た目が好みでないという理由だけでは改善需要を断定しない。

各指摘に確認URL、日時、画面幅、観察事実、具体的な改善案を残す。表示の指摘にはスクリーンショットを保存する。ブラウザ確認ができない候補は「未確認」として画像作成・送信を保留し、別の候補へ進む。

## 優先順位と提案

- 高：問い合わせに到達できない等の明確な支障、または異なる2項目以上の確認済みの支障があり、具体的な改善を提案できる。
- 中：確認済みの支障が1項目あり、具体的な改善を提案できる。
- 保留：確認できる支障がない、表示確認が不十分、事業者の意図が不明。件数のために問題を作らない。

高・中の候補を優先する。確認項目が複数あっても、初回の提案では最も意味のある改善点を1つに絞る。画像2点とメールの個別部分は、その1点の改善が分かる内容にする。初回の最後は関心を尋ねる質問1つとし、面談日時や予約リンクを同時に要求しない。料金・納期・対応範囲は `local-web-sales/daily-outreach/offer.json` のユーザー確定情報だけを使い、未確定なら仕様確認後の個別案内とする。「売上が上がる」「集客に困っている」「発注予算がある」と推測しない。営業拒否・フォームの用途制限を尊重する。

調査記録は `local-web-sales/daily-outreach/runs/<campaign>/website-reviews/<slug>.json` に保存する。例：

```json
{
  "company": "確認した事業者名",
  "industry": "業種",
  "region": "地域",
  "discovery_source": "候補発見元URL",
  "website_url": "公式URL",
  "checked_at": "タイムゾーン付き日時",
  "viewports_checked": [390, 1280],
  "findings": [
    {
      "category": "mobile_readability",
      "url": "実際に確認したURL",
      "viewport_width": 390,
      "observation": "実際に観察した事実",
      "evidence_path": "保存したスクリーンショット",
      "proposal": "具体的な改善案"
    }
  ],
  "priority": "high / medium / hold",
  "reason": "根拠"
}
```

未返信先への再連絡・追客・リマインドは基本なし。既送信の10件にも自動追客しない。

業種別の比較・配分最適化は今後、実データが蓄積してから行う。現時点で有効性を確定扱いしない。業種・発見元ごとに送信数、配信失敗、返信、関心のある返信、商談を区別して記録する。返信は実際のメール内容で判断し、自動返信を関心や商談に数えない。開封・受信箱への到達は送信済み表示から推測しない。次回の候補探しに観察結果を反映し、少数の結果だけで効果を断定しない。
